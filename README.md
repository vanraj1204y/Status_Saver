# Status Saver

A polished Flutter Android app to **save and share WhatsApp status photos and videos** that are already on your device. Built with a WhatsApp-inspired teal design language (Poppins + Roboto, rounded cards, light & dark themes) — but an original product, **not affiliated with WhatsApp**.

- **Package**: `com.statussaver.app` · **Version**: 1.0.0
- **Framework**: Flutter 3.44 (Dart 3.12) · **minSdk 24** (Android 7.0) · **targetSdk 35**

---

## Features

| Area | What it does |
|---|---|
| **Status detection** | Finds status images & videos WhatsApp keeps on the device (WhatsApp + WhatsApp Business), newest first, with thumbnails and video durations |
| **Preview** | Full-screen swipeable viewer — pinch-to-zoom images; real video playback (ExoPlayer) with play/pause, seek bar, ±10 s, mute, auto-hiding controls, error + retry |
| **Download** | One-tap save to the public gallery (`Pictures/Status Saver`, `Movies/Status Saver`) via MediaStore, with "Saved successfully" feedback and **duplicate detection** ("Already saved") |
| **Downloads gallery** | All / Photos / Videos tabs, open, share, delete (with confirmation), professional empty states |
| **Sharing** | Android share sheet with correct MIME types, plus a dedicated **Send to WhatsApp** action (`ACTION_SEND` + `setPackage`); falls back gracefully to the share sheet if WhatsApp isn't installed |
| **Themes** | Light / Dark / System Default — applied app-wide and persisted across restarts |
| **Settings** | Auto Save, save confirmations, video autoplay, mute-by-default, confirm-before-delete — all functional and persisted |
| **Help** | Beginner-friendly "How to Use" walkthrough |

## Screens

Splash (native + animated) → bottom-nav shell with **Statuses · Downloads · How to Use · Settings**, plus the full-screen media preview. All screens support light and dark themes and landscape.

## How status access works (per Android version)

Status files live in a hidden folder that WhatsApp maintains:

```
Android 10+ : /storage/emulated/0/Android/media/com.whatsapp/WhatsApp/Media/.Statuses
Android ≤ 9 : /storage/emulated/0/WhatsApp/Media/.Statuses
```

The access layer (`android/.../MainActivity.kt`, surfaced through `lib/services/native_channel.dart`) merges two sources and never assumes a single Android version:

- **Android ≤ 9** — `READ_EXTERNAL_STORAGE` runtime permission + direct file access (legacy path).
- **Android 10–12** — direct read of `Android/media` where the OS allows it; SAF fallback otherwise.
- **Android 13+** — scoped storage hides the dot-folder from MediaStore, so the app guides the user through a one-time **Storage Access Framework** grant. The system picker opens directly at the `.Statuses` folder; the user just taps *"Use this folder"*. The grant is persisted and survives restarts and reboots.

Saving always goes through **MediaStore** (API 29+) so downloads are visible in the system gallery, keep working after the source status disappears, and require no broad storage permissions. Stable file names (`StatusSaver_<original>`) provide duplicate detection.

## Architecture

MVVM with a thin native layer:

```
lib/
├── main.dart                  # Provider wiring, MaterialApp, theme mode
├── app/
│   ├── strings.dart           # every user-visible string (localization-ready)
│   └── theme/                 # design tokens from UI.png + light/dark ThemeData
├── models/status_media.dart   # StatusMedia, MediaType
├── services/
│   ├── native_channel.dart    # typed wrapper over the platform channel
│   ├── status_repository.dart # scanning, thumbnail cache, playable-file resolution
│   ├── download_repository.dart
│   ├── share_service.dart     # share sheet + Send-to-WhatsApp with fallback
│   └── settings_repository.dart  # shared_preferences persistence
├── viewmodels/                # Home / Downloads / Settings ChangeNotifiers
└── screens/
    ├── shell.dart             # bottom navigation + resume-refresh
    ├── splash/  home/  preview/  downloads/  howto/  settings/
    └── widgets/               # StatusCard, MediaThumb, SegmentedTabs, EmptyState,
                               # SkeletonGrid, AppToast, …

android/app/src/main/kotlin/com/statussaver/app/MainActivity.kt
└── single MethodChannel "status_saver/native":
    listStatuses · requestSafAccess · storage permissions · getThumbnail (cached,
    off-main-thread) · getPlayableFile · saveToGallery · listSaved · deleteSaved ·
    shareMedia (FileProvider) · openMedia
```

Key packages: `provider`, `video_player` (ExoPlayer), `shared_preferences`. Icons and native splash are generated by `flutter_launcher_icons` / `flutter_native_splash` from assets produced by `tool/gen_icon.dart`.

## Building & running

```bash
flutter pub get

# Develop (emulator/device)
flutter run

# Debug APK for an x86_64 emulator (small & fast)
flutter build apk --debug --target-platform android-x64

# Production build
flutter build apk --release          # → build/app/outputs/flutter-apk/app-release.apk (~47 MB)
flutter analyze && flutter test      # static analysis + tests
```

Install manually with `adb install -r build/app/outputs/flutter-apk/app-release.apk`.

> **Signing**: the release build currently uses the debug signing config (Flutter template default). Before publishing to Google Play, create a keystore and configure `signingConfigs` in `android/app/build.gradle.kts`.

### Regenerating branding assets

```bash
dart run tool/gen_icon.dart          # draws icon + splash logo PNGs
dart run flutter_launcher_icons
dart run flutter_native_splash:create
```

## Project quirks & troubleshooting

- **Rendering backend**: Impeller's OpenGLES path miscomposites overlays above video textures on some GPUs/emulators, so the app pins Skia via `io.flutter.embedding.android.EnableImpeller=false` in the manifest.
- **Emulator video decoder**: the Android emulator's `c2.goldfish.h264.decoder` occasionally fails on first init; the preview screen retries once silently before showing an error.
- **Huge debug APK (~430 MB)** is normal — AGP keeps native symbols for debuggable builds and Flutter's debug engine is unstripped. Release APKs are ~47 MB.
- **`dlopen: .dynamic section header was not found` at startup** means a corrupt Flutter engine jar in the Gradle cache. Verify: the SHA1 of the jar under `~/.gradle/caches/modules-2/files-2.1/io.flutter/...` must match its folder name. Fix: delete `~/.gradle/caches/modules-2/files-2.1/io.flutter` and rebuild.
- **Testing without WhatsApp** (e.g. emulator): push sample media to the status folder and grant SAF access to it —
  ```bash
  adb shell mkdir -p /sdcard/Android/media/com.whatsapp/WhatsApp/Media/.Statuses
  adb push photo.jpg /sdcard/Android/media/com.whatsapp/WhatsApp/Media/.Statuses/
  ```
